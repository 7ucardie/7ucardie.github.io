I'm Ellert van der Vecht, an engineer from the Netherlands. This is the first post here, so it should say who is writing and why this blog exists.

## Where I come from

I've been taking computers apart since I was seven. The first one was my brother's, and I put it back together well enough to show my teacher how it worked for an English exam. That curiosity about both hardware and software never left.

Since 2011 I've worked at [Schuberg Philis](https://schubergphilis.com), where my work sits at the intersection of engineering, development, security, and compliance. Most of my time goes into cloud infrastructure on AWS and Azure, and into the tooling that keeps enterprise systems observable, auditable, and safe to run.

## What I build

The projects on [my site](https://www.evandervecht.nl) give a fair picture of what I care about:

- **Central Observability Platform.** Monitoring for enterprise infrastructure, with compliance frameworks and AI-powered analytics built in rather than bolted on.
- **Transit.** An architecture diagram tool with an LLM assistant, risk analysis, and a monitoring dashboard.
- **SitesDrop.** Ephemeral static site hosting with version control and automatic expiry.
- **Security Audit Skill.** A security checkpoint framework spanning multiple languages, frameworks, and cloud providers, built as an agent skill.
- **TopoViz.** Cloud infrastructure topology in 3D, 2D, and network views, with a natural-language assistant. Open source, now shelved.
- **Costmodel Driven Run.** Cloud spend analysis and financial operations tooling. Cancelled, but it taught me a lot about how cost models actually get used.

Not everything ships. Some of these are on hold or cancelled, and I'd rather say so than pretend otherwise. The lessons from the ones that stopped are often more useful than the ones that went smoothly.

## Why a blog

My site has a [notebook](https://www.evandervecht.nl/notebook) for links, tools, and short notes. What it doesn't have is room for the longer form: the design decisions behind a project, the audit that found something surprising, the cost model that turned out to be wrong, the AI agent setup that finally worked.

That's what this blog is for. Most posts will come straight out of the repositories I work in, written up while the details are still fresh. Expect topics like:

- Cloud infrastructure and infrastructure-as-code on AWS and Azure
- Security auditing and compliance engineering, and how to make them part of the build instead of a gate at the end
- Observability platforms and what they should actually tell you
- AI and LLM tooling for engineering work, including agent skills and the security questions that come with them
- Cost analysis for cloud workloads
